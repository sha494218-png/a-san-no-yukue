# Aさんの行方 — 運営向け README

三重大学学園祭で実施する、周回型リアル脱出ゲームのWebサイトです。
参加者は自分のスマートフォンでこのページを開き、謎を解きながらキャンパス内を実際に歩いて周ります。

このREADMEは実装(`index.html`)と一致するように運営側で随時更新してください。

---

## 0. 現在の状態(重要)

謎1(パソコン)・マップ謎4問・交番の謎・ファイルの謎・LION謎は、**実際の問題文・画像・答えが入りました。**
ポスターの謎(任意)・最終問題(教室番号)・エンディング本文・合言葉(NO17CODE/LIONCODE)は
**まだ仮の値のままです。** 本番投入前に、下記「4. 本番投入までにやること(チェックリスト)」を確認してください。

**フォルダ構成**: このリポジトリ直下の `index.html`・`images/`・`fonts/` がそのまま公開ファイルです(GitHub Pages)。画像・フォントのファイル名はすべて英数字です(日本語名はURLで崩れやすいため。対応表は `images/README.md`)。

---

## 1. ファイル構成

```
index.html    ゲーム本体。この1ファイルだけで動作します(HTML+CSS+JS)。
README.md     このファイル。
images/       謎で使う画像を置く場所。
fonts/        同梱している明朝体・ゴシック体のフォントファイル(後述)。
test/         (このリポジトリには含めていません。運営のローカル環境のみ)
```

- **サーバーは使いません。** `index.html` をダブルクリックしてブラウザで開くだけでも動きますし、
  GitHub Pages や Netlify のような「ファイルをそのまま置くだけ」のホスティングにアップロードするだけで公開できます。
- npmやビルドツールは一切使っていません。`index.html` をテキストエディタで直接編集してください。

## 2. 編集方法(超重要: ここだけ触れば良い)

`index.html` の先頭付近、`const CONFIG = { ... };` という書き方をしている場所に、
ゲームの文言・答え・画像パスが**全部**まとまっています。

```js
const CONFIG = {
  gameTitle: "Aさんの行方",
  branchCodes: { ... },   // 現地の合言葉(後述)
  scenes: [
    { id: "puzzle_pc", type: "puzzle", ... },
    ...
  ],
};
```

謎の内容を直すときは、この `CONFIG` の中だけを編集してください。
`CONFIG` より下(`(function () { ... })();` の部分)は「エンジン」で、描画・答え合わせ・進捗保存などの
仕組みが書かれています。**通常はここを触る必要はありません。**

### 2-1. よく編集する項目

各謎(`type: "puzzle"` のオブジェクト)には、次のような項目があります。

| 項目 | 意味 |
|---|---|
| `heading` | 謎のタイトル |
| `optional` | `true` にすると「解かずに次へ進む」ボタンが出る任意の謎になる |
| `image` | 画像ファイルへのパス(`images/xxx.png`)。無い場合は `null` |
| `prompt` | 問題文。改行したい場所に `\n` を入れる |
| `answers` | 正解として認める答えの配列。表記ゆれ対策で複数書いてもよい(例: `["こたえ", "答え"]`) |
| `inputMode` | `"numeric"` にすると数字入力に最適化されたキーボードが出る |
| `hints` | 段階ヒントの配列。**配列の最後の要素は「答え」として表示されます。** |
| `reward` | 正解後に「手がかり一覧」に追加される情報。`label`(見出し)・`detail`(本文)・`kind`(種類、後述)。1つの謎で複数の手がかりを得る場合は配列で渡せる(謎1がその例) |
| `destination` | 画面上部に常時表示される「今の目的地」。移動が不要なら `null` |

謎1(パソコンのパスワード)を解くと、画面下部に「地図」ボタンが常時表示されるようになります。
マップ謎(謎2〜5)やLION謎は地図を何度も見返す前提の作りなので、このボタンからいつでも地図を拡大表示できます。
地図の画像パスは `CONFIG` 冒頭の `MAP_IMAGE` 定数1箇所にまとまっているので、画像を差し替えるときはここだけ直せば
マップ謎・LION謎・「地図」ボタンすべてに反映されます。

答えの一致判定はかなり寛容にしてあります(`norm()` という関数)。
全角/半角、大文字/小文字、カタカナ/ひらがな、空白や記号、長音符(ー)の違いを自動で吸収するので、
**答えは基本形だけ書いておけば大丈夫です**(例: `"0000"` と書けば `"００００"` も正解になります)。

謎1(パソコンのパスワード)には `lockScreen: true` が付いており、通常の画像の代わりに
PCのロック画面ふうの見た目(時刻・パスコードのドット表示)になります。ドットは実際の入力欄と連動して
自動で埋まるだけの飾りで、正誤判定には関係ありません。他の謎に流用したい場合はCONFIGで
`lockScreen: true` を付ければ同じ見た目になります(桁数は `maxLength` に従います)。

### 2-2. シーンの順番を変えたいとき

各シーンは `next`(または `nextTrue`/`nextNormal`)というプロパティで次のシーンIDを指定しています。
シーンの並び順そのもの(配列の順番)は表示に影響しません。**画面遷移は `next` の値だけで決まります。**
シーンを増やす場合は、新しいオブジェクトを `scenes` 配列に追加し、前後のシーンの `next` を書き換えてください。

### 2-3. 手がかりの種類(kind)

`reward` の `kind` には、次の6種類のいずれかを指定できます。指定しない場合は自動的に `"doc"` 扱いになります。

| kind | 表示ラベル | 用途の例 |
|---|---|---|
| `person` | 人物 | 依頼人の連絡先、ポスター制作者の名前など |
| `place` | 場所 | 交番の場所など、どこかの位置がわかる情報 |
| `photo` | 写真 | 写真そのものが手がかりになる場合(現状未使用。該当する謎ができたら使う) |
| `diary` | 日記 | Aさんの日記など |
| `doc` | 資料 | 指名手配の資料など、上記に当てはまらない書類・情報 |
| `map` | 地図 | 学内マップ |

`reward` に `image: "images/xxx.png"` を追加すると、手がかり一覧にその画像のサムネイルが表示され、
タップで拡大表示できます(謎1の「学内マップを入手」がその例)。

### 2-4. 日記の場面(縦書き)

`puzzle_file`(謎9)にだけ `diaryReveal` という項目があります。正解すると、通常の `reward` とは別に、
この内容で縦書きの専用画面が挟まります。

```js
diaryReveal: {
  before: "...",       // 縦書きの前に横書きで表示する文(地の文)
  vertical: ["...", "...", "..."], // ここだけ縦書きで表示される、Aさん本人の日記本文
  after: "...",        // 縦書きの後に横書きで表示する文(地の文)
},
```

他の場面には広げないでください(この場面だけが特別である、という演出上の意味があります)。

### 2-5. マップの訪問軌跡(SCENE_GRID_CELL)

`CONFIG` の外側にある `SCENE_GRID_CELL` という対応表で、「どのシーンが地図上のどのマス(1〜18)に対応するか」を
管理しています。ここに書かれている場所だけが、参加者が実際に解くと地図上に軌跡として表示されます。

```js
const SCENE_GRID_CELL = {
  puzzle_poster: null, // かるたサークルのポスター前 →【要記入】設置場所が決まったらマス番号に置き換える
  puzzle_koban: null,  // 特設交番 →【要記入】
};
```

**設置場所が決まるまで `null` のままにしておいてください。** 未訪問の場所や、LION謎で選ばなかった方の
分岐先(ライオン/NO17)を表示してしまうとネタバレになるため、勝手に埋めないことが重要です
(LION謎の分岐先だけは地図の描き込みから読み取れたため、`BRANCH_GRID_CELL` として別途設定済みです。
5章の「参考」を参照してください)。

マス番号は、地図を6列×3段のグリッドに見立てたときの番号です(左上が1、右下が18)。
グリッドの境界は `MAP_GRID` に画像に対する比率(0〜1)で持っており、`images/map.webp` を実際に解析して
測定した値を使っています。**地図の画像を差し替えた場合は、マス目の位置がズレる可能性があるので
再測定してください。**

### 2-6. 依頼人とのトーク(チャットUI)

物語(地の文)は、`type: "story"` ではなく `type: "chat"` のシーンとして、メッセージアプリふうの
吹き出しで表示します。`body` の代わりに `messages` という配列を持ちます。

```js
{
  id: "story_open",
  type: "chat",
  heading: "依頼人とのトーク【案】",
  messages: [
    { from: "system", text: "依頼人とのトークが始まりました" }, // 中央に小さく出る通知
    { from: "client", text: "はじめまして。ご相談したいことがあります。" }, // 依頼人(左・吹き出し)
    { from: "me", text: "わかりました。中を確認してみます。" }, // 自分(右・吹き出し)
  ],
  next: "puzzle_pc",
},
```

`from` は `"client"`(依頼人)・`"me"`(自分)・`"system"`(中央の通知)の3種類です。
「物語を振り返る」ドロワーでも同じ吹き出し形式で読み返せます。

### 2-7. フォントについて

明朝体(`--mincho`)・ゴシック体(`--gothic`)は、`fonts/` フォルダに同梱した
Noto Serif JP / Noto Sans JP(オープンライセンス、可変フォント)を `@font-face` で読み込んでいます。
外部CDNには一切依存しないので、オフライン気味の学内Wi-Fiでも表示が揺れません。

同梱しているのは、**現時点のCONFIGの文言で実際に使われている文字だけに絞ったサブセット**です
(全漢字を含めると1書体あたり数MB〜十数MBになり、学内Wi-Fiでの表示が遅くなるため)。
そのため、今後 `CONFIG` の文言を大きく書き換えて、今まで使っていない漢字を新たに使う場合は、
その文字だけシステムのフォールバックフォント(端末ごとの標準の明朝体・ゴシック体)で表示されます
(表示が崩れたり真っ白になったりはしません。その文字だけ書体が少し変わって見えるだけです)。
気になる場合は、Google Fontsで対象の文字を指定してサブセットを再生成し、
`fonts/NotoSerifJP-Variable.woff2` / `fonts/NotoSansJP-Variable.woff2` を差し替えてください。

なお、アナグラム謎で使っている「メイリオ」は商用フォントのため同梱していません
(端末にメイリオが無い場合はシステムの別のゴシック体で表示されます)。

### 2-8. マップ謎(4問)は順不同で解ける

謎2〜5(マップ謎)は一本道ではなく、`type: "hub"` の専用シーン(`map_hub`)から4問をまとめて表示し、
**参加者が好きな順番で解ける**ようになっています。

```js
{
  id: "map_hub",
  type: "hub",
  heading: "マップの謎",
  body: "4つの謎が見つかった。どれから解いても構わない。",
  puzzles: ["puzzle_map1", "puzzle_map2", "puzzle_map3", "puzzle_map4"], // ここに並べた謎を一覧表示する
  reward: { label: "...", detail: "...", kind: "place" }, // 4問すべて解いたときに1回だけ手がかりに追加される
  next: "move_poster", // 4問すべて解くと「次へ進む」ボタンが出て、ここに進む
},
```

- 各マップ謎(`puzzle_map1`〜`4`)は、通常の謎と同じ形式ですが `next` が次の謎ではなく
  `"map_hub"`(ハブ自身)になっています。1問解くとハブに戻り、残りの進捗が更新されます。
- ハブの `reward` は、個々の謎ではなく **4問すべて解き終えたときに1回だけ** 手がかりに追加されます。
- 謎の画面には常に「← 謎の一覧に戻る」リンクがあり、解かずにハブへ戻って別の謎から解き直せます。
- この「順不同のハブ画面」は `puzzles` 配列を書き換えれば他の場面にも流用できる汎用の仕組みです。

## 3. 参加者向けの便利機能

これらはエンジン側の機能で、`CONFIG` の編集なしにすべてのシーンで有効です。

- **全画面、紙基調**: 昼の屋外でも読めるよう、タイトル・トーク・エンディングを含む全画面を
  明るい地色+濃い文字で統一しています(以前の版にあった「物語画面だけ暗い背景」は廃止しました)。
- **地図をいつでも見返せる**: 謎1(パソコンのパスワード)を解くと、下部バーに「地図」ボタンが常時表示され、
  どの画面からでもタップで地図を拡大表示できます(2-1章参照)。
- **物語を振り返れる**: 依頼人とのトーク(chat)シーンを1つでも読むと、下部バーに「物語」ボタンが表示されます。
  タップすると、今までのやり取りをタブを移動せずその場で一覧表示できます(現在地は変わりません)。
- **画像の拡大縮小**: 画像タップで開く拡大表示(ライトボックス)は、スマホでは指のピンチ操作・ダブルタップ、
  PCではマウスホイール(トラックパッドのスクロールも可)・画面右下の「＋」「－」ボタンで拡大縮小できます。
  ドラッグ(スマホは指1本)で表示位置も動かせます。
- **ブラウザの「戻る」に対応**: スマホ・ブラウザの「戻る」操作(Androidの戻るボタン、ブラウザの←ボタンなど)で、
  1つ前に見ていたシーンに戻れます。「進む」で元の画面にも戻れます。戻っても解答状況や獲得した手がかりが
  消えることはありません(あくまで「今どのシーンを表示しているか」だけが変わります)。
  また、手がかり一覧・物語振り返り・画像拡大表示を開いている状態で「戻る」を押した場合は、
  シーンを移動せず、開いていたものを閉じるだけの動作になります(誤操作でシーンが進んだり戻ったりしません)。
- **日記の場面だけ縦書き**: 謎9(ファイルのパスワード)を解いた直後に出る、Aさんの日記を読む場面だけは
  縦書き表示になります(作中で唯一Aさん本人の声が直接出てくる箇所のため)。読みづらい場合は
  「横書きで読む」ボタンでいつでも横書きに切り替えられます。
- **手がかりを種類別に表示**: 手がかり一覧の各項目に、種類を示す小さなラベル(人物/場所/写真/日記/資料/地図)が
  付きます。写真・日記はAさん本人に近い情報として少し違う色で表示されます。
- **マップの訪問軌跡**: 「地図」で地図を開くと、実際に訪れた(=解いた)場所だけに枠とマス番号が表示されます。
  まだ訪れていない場所や、LION謎で選ばなかった方の場所(ライオン/NO17)は絶対に表示されません
  (どちらへ行くべきかという分岐の存在自体がネタバレになるため)。ライトボックス左上の「軌跡」ボタンで
  表示のオン/オフを切り替えられます(既定はON)。

## 5. 現地の合言葉(分岐)について

謎10(LION謎)を解くと、「ライオン」と「NO17」という2つの場所が示唆されます。参加者はどちらか一方に実際に移動し、
現地に設置された合言葉を入力します。

- `CONFIG.branchCodes` に2つの合言葉が定義されています。

  ```js
  branchCodes: {
    NO17CODE: { match: "NO17CODE", truth: true },   // 正しい場所(NO17)の合言葉 → TRUE END
    LIONCODE: { match: "LIONCODE", truth: false },  // 空振りの場所(ライオン)の合言葉 → NORMAL END
  },
  ```

- `match` の値を、それぞれの現地に掲示する実際の合言葉に書き換えてください。
  **`NO17CODE` `LIONCODE` のままでは、サイトのソースを見れば分岐条件がバレてしまいます。必ず変更すること。**
- どちらの場所にも辿り着けなかった参加者向けに、「どこにも辿り着けなかった(このまま進める)」ボタンがあります。
  これを押すと `LIONCODE` を入力したのと同じ扱い(NORMAL END行き)になります。

### 現地に設置するもの一覧(設置場所は要確定)

| 場所 | 設置するもの |
|---|---|
| かるたサークルのポスター前 | ポスター(謎6・謎10用) |
| 特設交番 | アナグラム資料(謎8)、合言葉の手がかりなど |
| ライオンの場所 | `LIONCODE` の合言葉掲示 |
| NO17の場所 | `NO17CODE` の合言葉掲示 |

※実際の設置場所・設置物は未確定です。決まり次第この表を更新してください。

**参考**: `images/map.webp`(競技かるたサークル作成の構内マップ)には、グリッド番号「17」(人文学部)と、
「14」付近に描かれたライオンのアイコンがあります。マップのデザイン上、この2箇所がそれぞれ
「NO17の場所」「ライオンの場所」に対応していると読み取れますが、**実際にその場所で合っているか、
現地に合言葉を掲示できるかは運営側で必ず確認・確定してください**(この読み取りが誤っている可能性もあります)。
この対応関係は `index.html` の `BRANCH_GRID_CELL` 定数(`{ LIONCODE: 14, NO17CODE: 17 }`)として、
マップの訪問軌跡機能(2-5章・3章参照)にも使われています。

## 6. スタッフモード

サイトのURLの末尾に `#staff` を付けてアクセスすると、スタッフ専用パネルが開きます。

```
https://(公開URL)/index.html#staff
```

- **任意のシーンへジャンプ**(参加者への説明・トラブル対応用)
- **謎の解答状態をリセット(デバッグ用)**: 選んだ謎1つだけを「未解答」に戻します。現在地・他の謎の進捗・
  獲得済みの手がかりはそのまま残るので、特定の謎の動作だけをその場で何度も確認したいときに使えます。
  マップ謎のハブ(`map_hub`)を選ぶと、中の4問もまとめてリセットされます。
  (再度解くと手がかりが重複して増えることがあります。気にせず使ってください。完全にきれいな状態で
  確認したい場合は下の「進捗リセット」を使ってください)
- **答え一覧**(全ての謎の答えと合言葉を一覧表示)
